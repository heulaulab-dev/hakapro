# KSEI >1% register: source and implementation facts (29 October 2026)

## Where the data comes from

IDX's [Share Ownership Data of Listed Companies](https://www.idx.co.id/en/listed-companies/share-ownership-data-of-listed-companies/) says its >1% shareholder list is obtained from KSEI. The Indonesian [Data Kepemilikan Saham](https://www.idx.co.id/id/perusahaan-tercatat/data-kepemilikan-saham/) page publishes the monthly files. This register is distinct from per-issuer IDX-BEI shareholder disclosures and from KSEI's other >5% or investor-type workbooks. The [mirror maintainer's source documentation](https://github.com/fzn0x/idx/blob/main/docs/ownership.md) describes the >1% XLSX layout and its discovery rules.

IDX challenges ordinary requests from cloud hosts. The existing HakaPro scheduler and importer use the fixed `fzn0x/idx` [`ownership-data` release](https://github.com/fzn0x/idx/releases/tag/ownership-data) as a transport mirror. Its `index.json` records the original IDX URL, month, file name, byte size, and SHA-256. The mirror maintainer describes its fetch, parse, and publish workflow [here](https://github.com/fzn0x/idx/blob/main/docs/ownership.md). **The index is not cryptographically signed**: comparing a downloaded file with its SHA-256 proves consistency with that index, not independent authenticity. Keep the original IDX URL and raw file hash as provenance; do not treat the mirror as a rights grant.

The live index fetched on 29 October was generated `2026-10-17T08:49:52Z`. Its latest file is **30 September 2026** (`ksei-above1-2026-09-30.xlsx`, 563,730 bytes, SHA-256 `804b3bb705860c8cee22addf63649c890d8cd66f8ae5e8a5d02730aec86bdd60`, [original IDX file](https://www.idx.co.id/Media/yqjhhsee/peng-2026-09-00024-satu-persen.xlsx)). **31 August 2026** is also available (`ksei-above1-2026-08-31.xlsx`, 562,877 bytes, SHA-256 `1d7cdb636054ce45c516666741f168348f97aba91771f4d0398ff84eae7c5e8f`, [original IDX file](https://www.idx.co.id/Media/fahlw1o2/peng-2026-08-00023-satu-persen.xlsx)). I downloaded both mirror assets and independently confirmed that their hashes match the index. The index lists 961 issuers in each month; it lists 7,157 August and 7,151 September holdings under the mirror's own parsing rules. HakaPro's accepted-row counts may differ, so UI counts must come from its Engine database.

## What the workbook actually contains

Both downloaded XLSX files have the same 12-column header on row 6: `DATE`, `SHARE_CODE`, `ISSUER_NAME`, `INVESTOR_NAME`, `INVESTOR_CLASSIFICATION`, `LOCAL_FOREIGN`, `NATIONALITY`, `DOMICILE`, `HOLDINGS_SCRIPLESS`, `HOLDINGS_SCRIP`, `TOTAL_HOLDING_SHARES`, `PERCENTAGE`. This matches the [mirror's documented schema](https://github.com/fzn0x/idx/blob/main/docs/ownership.md). In September, `INVESTOR_CLASSIFICATION` contains **labels**, for example `Individual`, `Corporate`, `Mutual Funds`, `Securities Company`, `Private Bank`, and `Bank`; it does not contain only the legacy `ID`/`CP`/`MF`/`SC`/`IB` type codes. `LOCAL_FOREIGN` contains `L`, `F`, or blank; the September file has 5,353 `L`, 1,592 `F`, and 209 blank lines. Preserve blanks as unknown. The workbook's own disclaimer says investor classification covers scripless holdings and may be absent for special scrip accounts; holder shares are compiled by SID or account where SID is unavailable. It also warns that earlier periods may be amended.

The KSEI [investor classification guide](https://web.ksei.co.id/Download/Panduan_Klasifikasi_Investor_Institusi.pdf) maps the older broad type codes to many finer classes, so displaying the workbook's class labels is more faithful than attempting to infer a broad type from a holder name. Class labels should be counted as **holdings/rows** unless holders are explicitly deduplicated by stable holder key. A count of disclosed foreign holders or disclosed foreign stake covers only published >1% lines, not total market foreign ownership. A `100% - sum(disclosed stakes)` remainder is not official free float. Conglomerate membership and public-figure identity do not appear in these 12 columns and require separately sourced, reviewed enrichment.

## Concrete HakaPro gap

`services/engine/src/ownership/layout.ts` maps `INVESTOR TYPE` but **does not map `INVESTOR_CLASSIFICATION`**. Thus the September upload stored `investorType: null` for rows that have a class label in the source. A 1% Screener investor-class breakdown based on current DB rows would be empty or misleading. Add a distinct classification field or a carefully named field mapping, preserve the original label, and reparse both months after the parser/storage update. The `F` local/foreign value must be handled explicitly. `scripts/import-ksei-ownership.ts` and the scheduled job select only the newest release, which explains why HakaPro has September but no August comparison. Backfill August from the verified fixed mirror. `deriveAfterUpload` in `services/engine/src/ownership/derive.ts` recalculates the next stored month, so importing August after September should populate September changes without reuploading September.

The repo's [Data Engine data-rights note](../features/DATA-ENGINE.md) says commercial reuse of KSEI data needs written permission. The file's `[PUBLIC]` label and third-party mirror do not themselves establish redistribution rights. Keep that release decision separate from engineering availability.
